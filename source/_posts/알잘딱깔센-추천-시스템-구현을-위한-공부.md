# 1. 추천 시스템이란?

추천 시스템은 특정 사용자가 좋아할 만한 것을 찾아주는 프로그램이다. 넷플릭스, 멜론, 스포티파이, 유튜브, 페이스북 등 우리가 일상적으로 사용하는 대부분의 서비스에 추천 시스템이 적용되어 있다.

<!-- more -->

대부분의 추천 시스템은 머신러닝을 기반으로 동작한다. 머신러닝이란 "어떤 작업을 할 때, 경험을 통해 그 작업에 대한 성능이 향상되는 프로그램"을 말한다. 추천 시스템에 대입해 보면 다음과 같다.



- **작업** = 추천
- **경험** = 유저의 행동 패턴 (데이터)
- **성능 향상** = 추천의 정확도 개선

### 1.1 추천 시스템은 어떻게 추천할까?

구매 이력, 평점 이력 등을 통해 상품을 추천한다. 유저의 행동 패턴이나 선호도를 많이 알수록 더 좋은 추천이 가능하다.

예를 들어 영화 추천 시스템에서, 상품에 대한 유저의 평점이 있는 데이터를 **평점 데이터(rating data)** 라고 한다. 유저가 평점을 주지 않아 빈칸으로 남은 데이터들이 존재하는데, 추천 시스템의 목표는 이미 주어진 평점들을 기반으로 **빈칸의 값을 예측**하는 것이다. 예상 평점이 높게 나온 영화를 유저에게 추천해주는 방식이다.

정리하면, 추천 시스템은 유저와 상품의 관계를 표현한 데이터를 사용해서 유저와 상호작용이 없었던 상품에 대한 선호도를 예측하고, 선호도가 높게 예측되는 상품을 추천한다.

<br>

## 1.2. 추천 시스템 데이터

### 직접 데이터 (Explicit Data)

유저가 직접적으로 상품에 대한 만족도나 선호도를 표시한 데이터다. 유저 선호도를 정확하게 나타낸다는 장점이 있다.

- 영화 평점 데이터 (1~5점으로 선호도 표시)
- 유튜브 좋아요/싫어요 데이터 (0, 1로 선호도 표시)

### 간접 데이터 (Implicit Data)

유저가 직접 선호도를 표시하지는 않았지만 행동으로부터 유추할 수 있는 데이터다. 수집이 쉽다는 장점이 있다.

- 유튜브 유저 영상 시청 기록
- 아마존 유저 구매 기록

간접 데이터도 직접 데이터와 동일하게 행렬 형태로 표현한다. 참고로, 정확하지만 적은 양의 데이터보다 다소 부정확하더라도 많은 양의 데이터로 학습하는 것이 더 나은 결과를 낼 수 있다.

<br>

## 2. 내용 기반 추천 (Content-Based Filtering)

### 개념

상품의 속성, 즉 **"어떤" 상품인지**를 사용해서 추천하는 방식이다. 상품의 속성들을 입력 변수로, 평점을 목표 변수로 설정하여 머신러닝 모델을 학습시킨다.

핵심 특징은 한 유저의 평점이 다른 유저의 평점에 영향을 미치지 않는다는 점이다. 즉 유저들의 평점이 서로 독립적이다.

### 장점

- 상품을 추천할 때 다른 유저의 데이터가 필요하지 않다
- 새롭게 출시한 상품이나 인기가 없는 상품도 추천할 수 있다

### 단점

- 적합한 속성을 고르는 것이 어렵다
- 선정한 속성 값들이 주관적일 수 있다
- 유저가 제공한 데이터의 범위를 벗어나는 추천을 할 수 없다
- 인기가 많은 상품을 더 가중해서 추천할 수 없다

<br>

## 3. 협업 필터링 (Collaborative Filtering)

"비슷한 유저들은 비슷한 상품을 좋아하지 않을까?"라는 아이디어에서 출발한다. 수많은 유저 데이터들이 **협업**해서 상품을 추천하는 방법이다.

### 3.1 비슷한 유저 정의하기 I — 유클리드 거리

가장 기본적인 협업 필터링은 비슷한 유저들을 찾아내서 이 유저들의 평점을 이용하는 것이다. 그렇다면 누가 비슷한 유저인지 어떻게 판별할까? **거리** 개념을 사용해서 유저들의 유사도를 평가할 수 있다.

**유클리드 거리(Euclidean Distance)** 는 두 데이터 포인트 사이의 직선 거리를 의미한다. 데이터가 숫자 하나라면 계산이 간단하지만, 차원(데이터 수)이 늘어날수록 복잡해진다. 두 데이터 사이의 유클리드 거리가 **작을수록 비슷하고, 클수록 다르다**.

<br>

### 3.2 비슷한 유저 정의하기 II — 코사인 유사도

데이터를 점이 아닌 **벡터(선)** 로 나타내서 **코사인 유사도(Cosine Similarity)** 를 사용할 수도 있다.

두 벡터 사이의 각도를 사용해 유사도를 측정한다. 벡터들이 서로 반대 방향이면 각도가 크기 때문에 취향이 다르고, 거의 겹치면 취향이 같은 유저라고 볼 수 있다. 이때 벡터의 크기(길이)는 사용하지 않고, 오직 방향만 본다.

각도를 그대로 사용하지 않고 코사인 함수에 넣어서 유사도로 활용한다. 코사인 값은 두 데이터가 비슷할수록 크고(최대 1), 다를수록 작아지므로(최소 -1) 유사도로 사용하기 적합하다.

<br>

### 3.3 유클리드 거리 vs 코사인 유사도

코사인 유사도의 가장 큰 차이점은 **벡터의 크기(magnitude)가 중요하지 않다**는 것이다.

구체적인 예를 들어보자. 유저의 구매 수량 데이터를 사용한다고 가정한다. 각 벡터의 원소가 [닭 가슴살, 아령, 맥주, 피자]라고 하면:

| 유저 | 닭 가슴살 | 아령 | 맥주 | 피자 |
|------|-----------|------|------|------|
| A | 1 | 1 | 0 | 0 |
| B | 100 | 50 | 0 | 0 |
| C | 0 | 0 | 1 | 1 |

직관적으로 A와 B는 비슷한 구매 취향을 가진 유저다. 하지만 유클리드 거리를 사용하면 B의 벡터가 매우 길기 때문에 A와 B가 오히려 멀다고 계산된다. 반면 코사인 유사도를 사용하면 A와 B의 벡터 방향이 비슷하기 때문에 A와 B가 더 유사하다고 올바르게 판단한다.

정리하면:

| 지표 | 값이 클수록 | 값이 작을수록 |
|------|------------|-------------|
| 유클리드 거리 | 다름 | 비슷함 |
| 코사인 유사도 | 비슷함 | 다름 |

<br>

### 3.4 유저 기반 협업 필터링으로 상품 추천하기

1. 대상 유저와 모든 유저의 유사도를 계산한다
2. 유사도가 높은 유저들의 그룹(이웃)을 선정한다
3. 이웃들의 해당 상품에 대한 평점 평균을 구한다
4. 이 과정을 반복해서 유저별로 예측 평점이 높은 상품을 추천한다

<br>

### 3.5 상품 기반 협업 필터링

앞선 내용이 비슷한 **유저** 를 이용한 추천이었다면, 비슷한 **상품** 을 이용하여 추천하는 방법도 있다.

1. 유사도를 사용해서 대상 상품과 비슷한 상품들을 찾는다
2. 비슷한 상품들의 평점 평균을 내서 유저가 대상 상품에 줄 예상 평점을 예측한다
3. 예측값이 높으면 추천하고, 낮으면 추천하지 않는다

이론상 유저 기반과 상품 기반 협업 필터링의 차이는 크지 않지만, 실전에서는 상품 기반 필터링의 성능이 더 좋은 경우가 많다. 유저가 상품보다 복잡한 특성을 가지기 때문이다.

<br>

### 3.6 협업 필터링의 장단점

**장점**

- 속성을 별도로 정의할 필요가 없다 → 평점 데이터만으로 다양한 상품에 동시 적용 가능
- 좀 더 폭넓은 상품을 추천할 수 있다
- 내용 기반 추천보다 성능이 더 좋은 경우가 많다

**단점**

- 데이터가 많아야 한다 — 유저 한 명이 열심히 평점을 줘도 다른 유저들의 데이터도 충분해야 한다
- 새로운 상품이나 유저에게 추천하기 힘들다 (Cold Start 문제)
- 인기가 많은 소수의 상품이 추천 시스템을 장악할 수 있다 (Popularity Bias)
- 어떤 상품이 왜 추천됐는지 정확히 알기 힘들다 (설명 가능성 부족)


<br>

### 3.7 어떤 방식을 사용해야 할까?

정답은 **둘 다 사용하는 것**이다. 예를 들어 아래처럼 여러 모델의 결과를 조합할 수 있다.

- 선형 회귀 기반 추천 3개
- 다항 회귀 기반 추천 3개
- 유저 기반 협업 필터링 추천 3개
- 상품 기반 협업 필터링 추천 3개

또는 위 4가지 방식의 예측값 평균을 내서 평균값이 높은 상품을 추천할 수도 있다. 여러 방식을 합쳐서 사용하면 각 모델의 단점을 보완하면서 장점을 살릴 수 있다. 이를 **앙상블(Ensemble)** 방식이라고 한다.

<br>


## 4. 행렬 인수분해 (Matrix Factorization)

### 4.1 개념

자연수나 다항식을 인수분해할 수 있듯이, 행렬도 행렬의 곱으로 분해할 수 있다.

핵심 아이디어는 다음과 같다: **유저의 영화 평점 = 유저의 취향 × 영화의 속성**. 즉, 평점 행렬 R을 유저 취향 행렬 P와 영화 속성 행렬 Q의 곱으로 분해하는 것이다.

$$R \approx P \times Q^T$$

행렬 인수분해를 사용하면 비어있는 평점들을 예측할 수 있다. 다만 모든 평점 데이터가 채워져 있을 때는 쉽게 분해할 수 있지만, 실제 데이터처럼 빈 값이 많은 경우에는 단순한 분해가 불가능하다. 이때 머신러닝 기법을 활용한다.

<br>

### 4.2 속성 학습 (Feature Learning)

평점 행렬을 구하기 위해 곱해야 할 유저 취향 행렬과 영화 속성 행렬, 총 2가지의 행렬을 학습해야 한다. 과정은 다음과 같다.

1. 유저 취향 행렬과 영화 속성 행렬에 **임의의 작은 값** 을 채워 넣는다
2. 두 행렬을 곱해 **평점 예측값** 을 구한다
3. 실제 평점(목표값)과 예측값의 차이를 **제곱 오차(MSE)** 로 비교한다
4. **경사 하강법(Gradient Descent)** 을 사용해 오차를 줄이는 방향으로 두 행렬을 업데이트한다
5. 수렴할 때까지 2~4를 반복한다

이렇게 데이터로부터 속성을 직접 학습하는 것을 **속성 학습(Feature Learning)** 이라 한다. 내용 기반 추천에서는 사람이 직접 속성을 정의해야 했지만, 행렬 인수분해에서는 모델이 데이터를 통해 자동으로 잠재 속성(Latent Factor)을 학습한다.


<br>


> 행렬 인수분해는 본질적으로 협업 필터링의 한 종류이기 때문에, 협업 필터링의 장단점을 그대로 공유한다.
> 
> 실전에서는 단일 기법보다 여러 기법을 결합한 **하이브리드/앙상블 방식**이 가장 좋은 성능을 낸다.
